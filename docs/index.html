Features

Everything a good commit history needs

Stop writing "fix stuff" or shipping 40 files in one commit. gitowl does the tedious part and leaves the decisions to you.

🧩

Smart grouping

Code goes with its tests, manifests with lockfiles, docs, CI and dependency bumps stay apart. Ordered so each commit builds on the previous one.

📏

Follows your rules

Reads AGENTS.md, CLAUDE.md, CONTRIBUTING.md, commitlint, Cursor and Copilot rules, and learns from your last 30 commits.

🎛️

You stay in control

Edit a title or the full message, regenerate, move files between commits, split, merge or skip. Nothing happens until you confirm.

✂️

Hunk-level splitting

A feature and an unrelated typo fix in the same file? --hunks sends them to different commits, only when it can prove the result is byte-identical.

🔒

Secrets never leave

API keys, tokens and private keys are redacted before anything is sent to a model. .env and *.pem files are never sent at all.

📝

Changelog in seconds

gitowl changelog builds release notes from your history without reading diffs, extends existing sections and copies your file's style.

🤖

Any model

Ollama, DeepSeek, Claude, Gemini, OpenAI, Groq, OpenRouter or any OpenAI-compatible URL. If a model fails you can switch on the spot.

🛡️

Safe by design

Your working tree is never touched, hooks run normally, and it never force-pushes or pushes a branch that is behind its remote.

🩺

Built-in doctor

gitowl doctor checks git, provider, key, model and rules, then tells you exactly how to fix whatever is off.

How it works

From messy working tree to clean history

  1. 1

    Scope

    Staged files only, or everything if nothing is staged. --all forces it.

  2. 2

    Plan

    The model splits the changes into commits. Every file is placed exactly once; anything it forgets is placed by folder and you are told.

  3. 3

    Review

    Edit, regenerate, move files, split, merge, skip, or ask for a new plan with guidance like "keep docs separate".

  4. 4

    Commit

    Each commit contains exactly its files. If a hook fails, retry, skip that commit or stop. Ctrl+C restores your staging.

  5. 5

    Push

    Ask, always or never, your choice. It shows the target, sets the upstream and warns you on main.

Your conventions

It already knows how your team writes commits

gitowl reads the rules that already live in your repo, nearest file wins, which is great for monorepos. Only the commit-related sections are extracted.

Changelog

Release notes without the busywork

  • Creates or updates CHANGELOG.md. Existing entries are never rewritten.
  • Finds missing releases from your tags, and extends the current section instead of replacing it.
  • Copies your file's style: flat or grouped, with or without brackets and dates.
  • Filters noise: merges, bumps, docs, test, chore, ci. Breaking changes are always kept.
  • AI is optional: --no-ai never calls a model.

API keys live in your system keyring (Windows Credential Manager, macOS Keychain, libsecret), never in the config file. Hosted providers do receive your redacted diffs. For private code, use a local Ollama.

Install

Up and running in a minute

npm install -g @carlosomarcr/gitowl
pnpm add -g @carlosomarcr/gitowl

Needs Node 20.19+. Gives you both gitowl and owl.

curl -fsSL https://raw.githubusercontent.com/carlosomarcr/gitowl/main/install.sh | sh

Also runs the setup wizard.

irm https://raw.githubusercontent.com/carlosomarcr/gitowl/main/install.ps1 | iex

PowerShell. Also runs the setup wizard.

Prefer no Node? Grab a standalone binary for Windows, macOS or Linux from the releases page.

$ gitowl init # wizard: provider, model, preferences
$ cd my-repo && gitowl
